# Glossary

> **Authority:** reference only — defines terms used across the `aimesh` monorepo and introduces no requirements; it inherits meaning from the documents it summarizes.

Terms used across meshcore, reviewmesh, and exploremesh. Each entry is labeled by the component that owns it: **[meshcore]** (the shared substrate library), **[reviewmesh]** (the review app), or **[exploremesh]** (the exploration app). See [architecture.md](architecture.md) for how the components fit together and [configuration.md](configuration.md) for config keys.

> **One word, two owners — read the label.** Three terms are deliberately per-app and never
> interchangeable: **Mode** ([reviewmesh] the write mode `report`/`patch`/`apply`; [exploremesh] the
> exploration contract `map`/`catalog`/`shortlist`/…), **Panel** ([reviewmesh] the ordered blind reviewer
> seats; [exploremesh] the explorers that participated in a run), and **Profile** (each app's own named
> configuration bundle, in different files — plus [reviewmesh] *canonical model profile*, a `modelCatalog`
> entry, which is a third thing again). Everything else in this glossary means one thing everywhere.

## Substrate: adapters, models, and identity

- **[meshcore] Adapter** — a `model` package implementation for one CLI/gateway (shell-recipe adapters for real CLIs — Claude Code, Codex, Antigravity/`agy`, Ollama, … — plus an internal test-only `fake` adapter, hidden, env-gated, and never user-configurable). Exposes atomic verbs (`Available` / `ValidateBinary` / `ProbeIdentity` / `Invoke` / `Caps`); provider-specific CLI flags never leak past it. See [adapters.md](adapters.md).
- **[meshcore] Adapter model argument (`modelArg`)** — the exact opaque string a given adapter passes to its underlying CLI for a catalog entry.
- **[reviewmesh] `authoritative`** — a per-model-catalog-entry flag (`modelCatalog.<key>.authoritative`). **The name overstates it:** it does *not* gate which model may fill the host/adjudicator role — that is decided solely by the profile's `lanes.author_remediator`. What it actually does is mark an entry as shipped or hand-authored and therefore **protected** from the setup housekeeping flows (saved-model overwrite, generated-model-key cleanup). Every seeded entry sets it `true`. An adapter-level `adapters.<name>.defaultAuthoritative` knob once existed and was removed as inert.
- **[meshcore] Name-bound vs. separable effort** — *name-bound* adapters encode the reasoning-effort tier in the model argument itself (e.g. Devin, Antigravity); *separable* adapters pass effort as its own flag (e.g. Codex, Claude, Gemini).
- **[meshcore] Model identity / evidence tiers** — the classification of how strongly a model call's identity is known, from strongest to weakest: `envelope > trace > cli_status > invocation_tag > self_report > none`. See [model-identity.md](model-identity.md).
- **[meshcore] verified / self_reported / unknown / mismatch** — the four identity outcomes derived from the evidence tiers. `verified` and `self_reported` responses are usable (the latter with a caveat); `unknown` is a weak pass-with-caveat; `mismatch` is strong evidence the responding model is not the requested one.
- **[meshcore] Containment** — running a model against a disposable, isolated copy of a workspace so it cannot mutate the live tree; only the host applies accepted changes to the live workspace. Implemented by the `workspace` package.
- **[meshcore] Confinement / trusted root** — the set of directories a human authorized a run to touch, resolved by the one `scope` resolver every surface funnels through. On the CLI the path you type *is* the consent; over ACP and MCP the caller is a peer process, so consent is given at launch with `--root` (or the launch working directory, when it is a plausible project). A request may narrow the set and can never widen it; with no roots, every path is refused (`scope_no_roots_configured`) — "no roots" is never "unrestricted".
- **[meshcore] Non-overridable denylist** — the paths refused *inside* an allowed root: `.env*`, credential directories and key material (read **and** write), plus `.git/**`, this tool's own state/config and agent/IDE client configuration (write, and excluded from the containment copy). Matched per path component, so a denied directory denies its whole subtree. Not configurable, and not waived by `--allow-broad-root`.
- **[meshcore] Withheld file** — a file a containment rule kept out of the reviewed set without stopping the run (today: a hardlinked regular file, whose innocuous in-tree name may be a second name for protected material). Never silent: every withhold is carried as a caveat in `run-state.json`, the `--json` projection, the ACP/MCP result and the CLI summary — because a reviewer cannot object to a file it was never shown.
- **[meshcore] M5** — the containment-breach halt: the isolated copy was mutated out-of-band (a mechanical check, not a call-result class).
- **[meshcore] M6** — the **scope-refusal** halt: a read or write outside every allowed root, or to a denylisted path. Distinct from M5 (which is "the model mutated the copy"); both exit `6`.
- **[meshcore] Halt taxonomy** — the classification of call and mechanical-check results into halt classes with deterministic exit codes: **A–G** for adapter/model calls (e.g. A auth/binary problem, D requested model unavailable, G unparseable/schema-invalid output) and **M1–M6** for mechanical checks (M5 unexpected mutation, M6 scope refusal). Owned by the `fault` package. Both binaries map a class to an exit code the same way — see [architecture.md → Halt taxonomy](architecture.md#halt-taxonomy).
- **[meshcore] `reasonCode` / `signal`** — the stable *machine* fields on a halt record and a call status: `reasonCode` names the rule that refused (e.g. `scope_read_denied`, `authority_budget_exceeded`), and the optional `signal` classifies an actionable provider-CLI blocker (folder-trust / login-required / model-invalid / update-prompt). Branch on these, never on the human message text.
- **[meshcore] MCP transport** — the generic Model Context Protocol stdio plumbing in the `mcp` package. It is **dual-era**. LEGACY (`2025-06-18`, `2025-03-26`, `2024-11-05`) is session-based: `initialize` + `notifications/initialized`, `protocolVersion` negotiation, `tools/list` paging, `tools/call`, progress, cancellation, `ping`, `logging/setLevel`, `resources/*`, and server→client `roots/list`. MODERN (`2026-07-28`) is sessionless: `server/discover`, the per-request `_meta` protocol context, `resultType` + caching hints + `serverInfo` on every result, and the opt-in `io.modelcontextprotocol/tasks` extension. The modern era deliberately **removes** `ping` and `logging/setLevel` (`-32601`), emits **no** `notifications/message` at all, and issues no server→client requests. It knows no tools; each app registers its own. See [mcp.md](mcp.md).
- **[meshcore] Protocol era / era latch** — a process serves ONE MCP family for its lifetime: `legacy` (session-based, `2025-06-18` and older) or `modern` (`2026-07-28`, sessionless). The **latch** is an atomic compare-and-set taken only after a request has fully validated, so a malformed or unsupported-version opener never decides the era; the loser of a cross-era race gets a teaching refusal naming `--protocol`. `--protocol dual|legacy` sets the launch posture. See [mcp.md § The two eras](mcp.md#the-two-eras-and-how-a-request-picks-one).
- **[meshcore] `resultType`** — the `2026-07-28` discriminator every modern result carries. On this surface it takes two values: `"complete"` (the result is final) and `"task"` (a handle, for a client that opted into the tasks extension). It is absent on the legacy era, where clients must read an absent value as `"complete"`. Do not confuse it with a run's `state` (`running`/`complete`/`halted`/`cancelled`), which is domain data inside the payload.
- **[meshcore] Caching hint (`ttlMs` / `cacheScope`)** — the `CacheableResult` fields the modern era attaches to the six cacheable operations (`server/discover`, `tools/list`, `prompts/list`, `resources/list`, `resources/templates/list`, `resources/read`). `ttlMs` is a freshness hint in milliseconds; `cacheScope` is `"private"` everywhere here. `ttlMs` on a `tasks/get` result is a **different quantity** — task lifetime, not a cache hint.
- **[meshcore] `io.modelcontextprotocol/tasks` extension** — the modern-era, opt-in-per-request extension this transport implements as a **projection over the existing run registry**, `taskId == runId` always. The server advertises it in `server/discover`; a client opts in per request via `_meta`. A client that does not opt in sees exactly the job shape. See [mcp.md](mcp.md#the-iomodelcontextprotocoltasks-extension-modern-era-opt-in-per-client).
- **[meshcore] Class E** — the model-fault halt class. **No identity classification is Class E.** A `verified`, `self_reported`, `unknown` or proven `mismatch` identity is recorded as a caveat and the response is used; see [model-identity.md](model-identity.md) for why a claim a model cannot be made to prove is not allowed to fail a run.
- **[meshcore] Config store** — the governed configuration read/write path: atomic writes, raw-map load, and validated patch application. The validator is supplied by the calling app, so meshcore itself never learns an app's config schema. Owned by the `config` package.
- **[meshcore] ConfigPatch** — a declarative set of config changes (an ordered list of set/delete operations) applied through the config store by an app's setup flow, guided repair, or config UI; never contains secrets.
- **[meshcore] doctor / readiness** — domain-free readiness primitives (adapter availability probes, writable-dir checks, a `Prober` interface, `Check`/`Report` types) that each app's `doctor` command builds on.
- **[meshcore] verify-on-provision** — a recipe, field, or behavior that is implemented and fake-tested now but can only be *confirmed* once an external resource is available (an authenticated CLI, a real ACP host, a git/CI repo).
- **[meshcore] ACP transport** — the generic Agent Client Protocol JSON-RPC plumbing (newline or `Content-Length` framing, a cross-restart session store, child-process harness utilities) in the `acp` package. App-specific protocol *validation* stays in the app; meshcore has no ACP domain opinions.
- **[meshcore] Audit** — domain-neutral run plumbing (run directories, event logs, per-call records) in the `audit` package, used by both apps to write their run artifacts.

## reviewmesh: roles, lanes, and modes

- **[reviewmesh] Role** — a function in the review sequence: `author_remediator` (the host/adjudicator), `reviewer`, `cross_check`, `verifier`. A role is configuration, not a component.
- **[reviewmesh] author_remediator** — the host role: adjudicates findings and, depending on mode, applies the accepted changes. The only role that writes.
- **[reviewmesh] reviewer** / **cross_check** — analysis-only roles that produce `Finding`s; never write.
- **[reviewmesh] verifier** — a pass that re-checks the workspace after cross-check-driven changes.
- **[reviewmesh] Provider lane** — the model *provider* assigned to a role (`anthropic`, `openai`, `google`, …). Never a transport.
- **[reviewmesh] Canonical model profile** — the structured identity of one model (provider, family, model, effort) plus its per-adapter execution arguments; a `modelCatalog` entry.
- **[reviewmesh] Runtime profile** — a named, selectable bundle of role→model lane assignments (the `profiles:` config block); also called a *preset*. Distinct from a canonical model profile.
- **[reviewmesh] Finding** — the structured unit of review output a reviewer/cross_check/verifier produces; validated against [`reviewer-result.schema.json`](schema/reviewer-result.schema.json).
- **[reviewmesh] Adjudication** — the host judging each finding's validity and severity, then deciding report/patch/apply.
- **[reviewmesh] Remediation** — the host turning an accepted finding into concrete `Edit`s (search/replace blocks) and applying them.
- **[reviewmesh] Addressed-context** — the dispositions of prior findings (`applied`, `already_addressed`, `skipped`, `upstream_conflict_deferred`, or `invalid` with a rejection reason) fed into later review passes, including the cross-check reviewer, so reviewers focus on novel issues and don't re-raise a rejected finding unless they explicitly disagree with the reason.
- **[reviewmesh] Stabilization** — the condition that ends the primary reviewer's inner loop: approve, set-stable (finding set unchanged across two passes), or all remaining findings judged invalid; bounded by an inner-iteration cap.
- **[reviewmesh] Outer cycle / inner iteration** — an outer cycle is one full review → adjudicate → remediate pass; inner iterations are the primary reviewer's repeated passes within an outer cycle until stabilization. The cross-check runs once per outer cycle.
- **[reviewmesh] Mode** — what the host does with accepted findings: `report` (findings only), `patch` (emit a diff), `apply` (write changes). Effective mode = `min(requested, surface-permitted, policy-permitted)`.
- **[reviewmesh] Host surface** — where a run was driven from: `cli`, `ci`, `acp`, or `mcp`. Independent of the adapter.
- **[reviewmesh] Surface ceiling / capability** — a surface's **write-authority ceiling** is its `surfaces.defaultModeBySurface` entry (shipped `cli: apply`, `ci: report`, `acp: report`, `mcp: report`); a request may resolve narrower, never wider. Despite the field name it is a **ceiling, not a default**: a run naming no mode resolves to `report` on every surface, so `cli: apply` permits `--apply` rather than making a plain run write. A **capability** in `surfaces.capabilitiesBySurface` *raises* that ceiling — today only `allowRemediate`, which `aimesh review mcp --allow-remediate` grants in that server process's own config snapshot. Because the ceiling is computed *from* the config, a grant raises it rather than stepping around it. See [configuration.md](configuration.md#surface-ceilings-and-capabilities).
- **[reviewmesh] Blind reviewer panel / seat** — the primary review stage: an **ordered** list of 1..16 *seats*, each a distinct `(adapter, model, effort)` vantage. Every seat runs in parallel and sees only the workspace and its **own** earlier rounds — never a peer's findings, never host decisions. N requested is N executed or the run fails; `cross_check` and `verifier` are separate roles, never seats.
- **[reviewmesh] Agreement count / supporting seats** — per finding, the seats that reported it, the seats that ran and did *not*, and the resulting count. **Computed by the host**, never asserted by a model; the reviewer schema has no field an agreement could ride in. Each supporting seat also carries its model-identity tier, so a reader can see what the support consists of — but a weak tier never changes what happens to the finding (see [model-identity.md](model-identity.md)).
- **[reviewmesh] Authority / context document** — a requirements doc, design doc, ADR or spec the reviewed artifact is judged **against**. Context, never a target: never reviewed, patched, applied, or placed in the containment copy — it is prompt-embedded, so the write layer cannot reach it by construction. Declared identically on all three surfaces (`--authority`/`--authority-manifest`, ACP `_meta.reviewmesh.authority[]`, MCP `authority[]`).
- **[reviewmesh] Write-path rule** — every applied hunk must trace to evidence in the **workspace copy**. A finding supported only by authority text is reported and marked `applyable: false` (`applyRefusalReason: authority_only`), never written. It is the rule that still holds if prompt injection succeeds.
- **[reviewmesh] Recorded refusal (protected path)** — a finding whose target is a **protected path** (meshcore's non-overridable write denylist) is marked `applyable: false` with `applyRefusalReason: protected_path`, the *remaining* findings are still applied, and the refusal is surfaced as a first-class fact. Nothing is ever written to a protected path; what changed is that one out-of-bounds target no longer discards the whole paid run. It is deliberately **not silent** — that was the objection the old halt answered: the run reports itself as not cleanly successful on every surface (CLI exit 7 with `apply_refused_protected_path` and *no halt record*, MCP `isError: true` + `outcome: partial_refusal`, ACP `stopReason: refusal`), always paired with `counts.applied` so "one was refused" cannot be misread as "nothing was written". Refusals are keyed on the **host-computed fingerprint**, never the model-authored finding id. Unlike the other three refusal reasons, which describe findings that were never *eligible* to be applied and still exit 0.
- **[reviewmesh] Inclusion manifest** — the per-document record of exactly which authority bytes reached the prompt: source, full-content hash, embedded-content hash, bytes embedded/total, completeness, declared ranges. Makes "which intent was this judged against" a recorded fact.
- **[reviewmesh] Setup wizard** — the interactive flow (`aimesh review setup --interactive`) that picks a profile to configure, captures a validated adapter binary path, offers per-role model selection from the catalog, and writes config to a chosen scope.
- **[reviewmesh] Repair wizard** — the interactive flow (`aimesh review doctor --fix`) that walks through fixing each issue `doctor` found, keyed to its halt class, then re-checks.
- **[reviewmesh] Run directory** — the per-run audit folder (`.aimesh/review/runs/<run-id>/` when a `.aimesh/` state directory exists, else under the OS temp directory; `REVIEWMESH_ARTIFACT_DIR` overrides) holding JSON state and Markdown summaries. Distinct from the ephemeral containment copy.

## exploremesh: explorers, collation, and disagreement

- **[exploremesh] explorer** — one `(adapter, model, effort)` triple, unique by the full triple, that answers a task blind and in parallel with the other explorers. A run requires a **minimum of 2**.
- **[exploremesh] collator** — exactly one `(adapter, model, effort)` that terminates a run by **synthesizing** the explorer responses (and, in multi-round modes, by mediating between rounds). It may reuse an explorer's model for a different function/prompt. It does **not** author the round-1 payload — see *formulation-free*.
- **[exploremesh] task (`raw_task`)** — the per-run input: `{ purpose, criteria[], prior_context?, mode? }`, plus the mode's own declarations (an artifact for `challenge`; options + criteria for `compare`; target/unit/horizon for `forecast`).
- **[exploremesh] explorer_task_payload** — the round-1 payload `{ final_prompt, expanded_schema }`, byte-identical for every explorer in the round, persisted, hashed, and audited. The only variable across explorers is `(adapter, model, effort)`.
- **[exploremesh] formulation-free** — every registered mode owns its explorer prompt **and** response schema in app code, so the collator never authors what explorers are asked. This closes the *collator-as-common-cause* problem: a model that wrote the shared frame could bias every "independent" answer at once (and, in a real dogfood, wrote a schema that contradicted its own instructions). `Formulation.Source` records this provenance as a positive assertion; it is no longer a branch.
- **[exploremesh] Mode** — the app-owned exploration contract selected with `--mode`: `map` (default), `synthesize`, `catalog`, `challenge`, `shortlist`, `ai-collab`, `compare`, `forecast`. Each owns an explorer prompt, an explorer schema, a collator objective, and an output schema.
- **[exploremesh] Emergent- vs fixed-space** — whether the answer space is discovered by the explorers or declared by the user up front. *Emergent* (catalog/challenge/shortlist/ai-collab) needs entity resolution, so its counts rest on a recorded canonicalization; *fixed* (compare/forecast) declares its options/target before anyone speaks, so its results are purely host-deterministic with no canonicalizer at all.
- **[exploremesh] Canonicalization / merge-ledger** — resolving "did two explorers name the same thing?" into canonical IDs. The decision is a model judgment, so it is **recorded, not hidden**: an append-only, hash-chained ledger maps every raw nomination → canonical ID with the deciding call and identity. Count/ballot-bearing modes use **two independent canonicalizers** and keep only merges both propose (a contested merge is *split* — splitting can undercount corroboration but can never manufacture it); observe-posture `catalog` uses a single canonicalizer and no confirmation round.
- **[exploremesh] Surjectivity gate** — the mechanical form of minority carry-through: every raw nomination must appear in exactly one ledger row and every canonical ID must be reachable. De-duplication may *cluster*, never *drop*.
- **[exploremesh] Partition revision hash** — the hash of the ledger revision a count was computed at. Every emergent-space claim is pinned to one, so a number can always be traced to the exact partition that produced it.
- **[exploremesh] Blind baseline / anti-echo** — independence-based counts are computed **only** over immutable blind round-1 artifacts. Later rounds add depth but may never re-derive counts, so agreement produced by a mediated digest can never masquerade as independent corroboration.
- **[exploremesh] emergent vs voted** — *emergent* = host-counted independent mentions in blind round 1 (salience, not merit); *voted* = an explicit ballot over confirmed canonical IDs. A ballot is informed preference under shared framing and is never rendered as consensus.
- **[exploremesh] Profile** — a named, ordered explorer set + a collator + an optional default mode, in `~/.aimesh/explore/profiles.yaml`.
- **[exploremesh] Preference order** — a profile's authored explorer order, used **only** to select the top-N under `--count`. It is deliberately decoupled from attribution order, so reordering a profile never changes the envelope IDs of an unchanged selected set.
- **[exploremesh] Ad-hoc roster** — a one-off panel named directly on the command line (`--explorer adapter=…,model=…`), bypassing profiles, validated against the configured adapters.
- **[exploremesh] Disagreement register** — the collator's synthesis of where explorers diverge: subject → per-explorer positions with evidence → resolution → residual risk.
- **[exploremesh] Weak-response appendix** — where a weak-identity (`self_reported`/`unknown`) explorer's response is carried, kept out of the primary synthesis (which requires ≥ 2 verified explorer responses) but not discarded.
- **[exploremesh] Panel** — the set of explorers that actually participated in a run (after any drops for identity or call failure). Counts report **dual denominators**: `k of M panel` and `k of (M − non-respondents) respondents`.

## reviewmesh internal architecture (IDesign pattern)

These terms describe reviewmesh's own internal component layering; they are not part of the public API surface but appear in code comments and internal design docs. See [architecture.md → The application pattern](architecture.md#the-application-pattern) for the full shape (Clients → Managers → Engines → meshcore → Resources).

- **[reviewmesh] Client** — a host surface (CLI/ACP/web) that calls only a Manager.
- **[reviewmesh] ReviewManager** / **SetupManager** — the two Managers: review's sole adjudication/live-write authority, and setup/repair's sole config-store writer, respectively.
- **[reviewmesh] Engine** — a component encapsulating one volatile activity (`AdjudicationEngine`, `RemediationEngine`, `SetupEngine`).
- **[reviewmesh] ResourceAccess** — a component reaching a resource through atomic business verbs, never CLI/IO specifics (`ModelAccess`, `WorkspaceAccess`, `AuditAccess`, `ConfigAccess`).
- **[reviewmesh] Closed architecture** — a component calls only one layer down, never up or sideways (Utilities excepted); the two Managers never call each other.
